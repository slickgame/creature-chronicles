# Connected Breeding Pen window review

The user requested work on all eight destinations from the approved Breeding Pen. This is the current-screen audit and design-review stage, before choosing the new layouts. The live application components are unchanged.

`public/previews/breeding-windows/index.html` provides two layout families for all eight windows. The separate preview toolbar chooses A/B and the destination; it is review tooling, not a proposed in-game global navigation row. `overview.html` compares the actual current screens with both concepts. The sample model comes from an isolated QA save and existing preview/inheritance/item helpers. Canonical profile and apothecary artwork is reused unchanged. All prototype actions are read-only simulations; they cannot use items or perform live breeding attempts.

A is the compact workbench family: galleries/rows, explicit selected inspectors, adjacent comparison values and compact cost confirmation. B is the roomy dossier family: larger profiles, a narrow candidate rail, focused records and a lineage-book composition. Both reuse the approved wood header, navy/gold frames and emerald/cream action hierarchy. Full figures, explicit Back, phone focus views and source return remain requirements. Suggested default: A across the tool-heavy windows; B remains an option when large creature artwork is preferred, especially Inspect and Change.

Current capture: eight real application windows at desktop and phone, with browsing/closing leaving the isolated gameplay save unchanged. Proposed layouts: A/B × eight windows × desktop plus two phone focus views (48 captures), checked for image loading, visible text/viewport bounds and panel containment. Interaction checks also verify opposite-parent blocking, inspecting the chosen candidate, no-effect supply blocking, available pair support review, unchanged browser storage and zero non-read network requests. Source scripts are capture-breeding-window-review.mjs, capture-breeding-window-concepts.mjs, capture-breeding-window-boards.mjs and validate-breeding-window-prototypes.mjs. Source model preparation uses prepare-breeding-window-review.ts and does not access a user save or service.

Implementation should follow the selected layout(s), beginning with the shared window shell, then Inspect/Change, Support/Inheritance, Pair Options/Chance/Review and Ledger. Preserve each parent window's selection, tab and source across nested details. Include desktop, phone, short landscape, empty/partial, unavailable, depleted-stock, stale-review and duplicate-confirmation verification when wiring the runtime.

The repository review rule in AGENTS.md calls for current screenshots and distinct concept options before implementing a new window direction. No runtime replacement, merge or production transaction is part of this review. PR21 stays draft and unmerged.
